# CAD & Scan-to-Digital-Twin Rules
- **Python Environment:** Always execute CAD and point-cloud scripts using `~/cad-env/bin/python`.
- **Scan-to-CAD Workflow:** Follow `~/.claude/skills/cad-skill/SKILL.md`. Use `open3d` and `trimesh` to clean, align, and slice raw 3D scans (`~/.claude/skills/cad-skill/outline_from_scan.py`) before generating parametric CAD geometry. Never dump raw `.ply`/`.obj`/`.stl` vertex coordinates into chat context.
- **CAD & Export Standards:** Use `build123d` or `cadquery` for parametric parts (in millimeters, Z-up). Always export `.step` for engineering CAD and `.stl`/`.glb` for 3D printing and digital twin pipelines.
- **Mandatory Visual Inspection:** Before finishing any 3D modeling or scan-reconstruction task, render multi-view PNGs using `GALLIUM_DRIVER=llvmpipe LIBGL_ALWAYS_SOFTWARE=1 PYOPENGL_PLATFORM=egl xvfb-run -a ~/cad-env/bin/python ~/.claude/skills/cad-skill/preview.py model.stl preview.png --views multi --strict` (or PyVista/Trimesh with the same three variables) and inspect the rendered PNG images using your Read tool to verify watertightness and accuracy.
- **Software Rendering Only:** The login shell sources `~/picogk/env.sh`, which exports `GALLIUM_DRIVER=d3d12`. Off-screen renders through d3d12 hung the GPU and stopped WSL twice on 2026-11-12, killing the session and every running solver. Keep the llvmpipe prefix on every off-screen render; d3d12 is for PicoGK's own viewer only.
