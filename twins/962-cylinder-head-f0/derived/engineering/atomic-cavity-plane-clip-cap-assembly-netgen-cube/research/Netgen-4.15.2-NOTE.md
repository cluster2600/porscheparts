## What Netgen actually changes

`src/mesh/Generator.cpp:956–961` dispatches method`Netgen` separately from the default optimizer and sets volume orientations positive afterward. `meshGRegionNetgen.cpp:342–375` requires a nonhybrid tetrahedral region, bypasses the discrete-volume early return only with`force=True`, imports current boundary/interior/tetrahedra, deletes the volume mesh, runs Netgen and transfers its output. The same file:27–105 puts existing surface vertices first and imports the oriented surface triangles;:110–156 retains those boundary MVertex objects and creates new objects for referenced nonboundary points and every output tetrahedron. It does not transfer a new surface mesh back to Gmsh.

The Gmsh-specific implementation is **`contrib/Netgen/nglib_gmsh.cpp`**, not the upstream`nglib/nglib.cpp`. Its:225–243 calls`RemoveIllegalElements` then`OptimizeVolume` without generating a new volume from scratch. `meshfunc.cpp:619–674` dispatches combine, split, swaps and smoothing;`meshtype.cpp:2589–2593` defaults to three`cmdmustm`passes (the surface-swap`u`case is commented out). `improve3.cpp:143–155` refuses removal of a boundary endpoint and leaves a boundary target fixed;:500and532 insert points during splitting. `smoothing3.cpp:1241` limits that smoother to interior points. Netgen therefore can replace internal connectivity, remove/insert/move interior points, and Gmsh can retag/recreate all interior vertices even if some coordinates do not move. No old-to-new interior ancestry is promised.

This is source support for a new hypothesis, not a proof that this installed runtime preserves a particular head boundary or meets SICN0.1. Netgen's own badness/legality criteria are not that scientific acceptance gate. The Netgen return value at the adapter call is not itself propagated as a full quality certificate; capture native errors and require every independent output gate.

## Saved-discrete-region obstruction and smallest preparation change

A plain`open(saved.msh)`→`optimize(Netgen,force=True)`is unsafe to assume sufficient. MSH4 creates`discreteRegion`(:443/569 of`GModelIO_MSH4.cpp`) with `_geometry=false`(`discreteRegion.cpp:10–18`). `GRegion::isFullyDiscrete`(:962–978) can then return true;`deMeshGRegion`(`meshGRegion.cpp:230–234`) returns without deleting that mesh. Netgen's outer force guard still permits entry, while`TransferVolumeMesh`appends new tetrahedra. This source path can retain old tetrahedra instead of replacing them; it is not merely an ID-comparison issue.

The smallest source-supported adaptation to test is **volume-only**`gmsh.model.mesh.createGeometry([(3,1)])`before the optimizer. `gmsh.cpp:5671–5675`dispatches to`GModel.cpp:2538–2544,2583–2588`; for dim3 only,`discreteRegion::createGeometry`(:22–32) requires nonempty bounding surfaces then sets `_geometry=true`. It neither parametrizes the surface nor changes mesh arrays. This makes the volume-deletion guard false. Do not call unconstrained`createGeometry()`or select dim2, and do not add a surface remesher, new boundary, geometric tolerance or source reconstruction.
