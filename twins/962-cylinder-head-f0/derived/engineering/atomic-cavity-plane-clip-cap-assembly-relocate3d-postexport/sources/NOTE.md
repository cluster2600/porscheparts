Exact Gmsh 4.15.2 `Generator.cpp:1015-1019` forwards API niter to the volume relocation routine. `meshRelocateVertex.cpp:459-475` performs niter+2 full vertex-star sweeps: the selected niter=1 means three sweeps, not one. Unlike the Netgen branch, the argument reaches this backend. `meshRelocateVertex.cpp:327-362` changes coordinates only for dimension-3 vertices, without creating/removing nodes or replacing tetra connectivity. Its branch does not inspect force or the discrete-volume geometry flag: this hypothesis supplies no force argument and does not call createGeometry. `GModel.cpp:1531-1540` still applies periodic correction/optional renumbering after optimization; the existing absent-periodicity guards and Mesh.Renumber=0 remain mandatory. API dimTags is not a reliable scope restriction in this release; the wrapper instead requires exactly volume(3,1) and a nonempty bounding shell.

The objective is the minimum incident-star signed Gamma (`meshRelocateVertex.cpp:48-80`), with Gamma based on 3*inradius/circumradius (`qualityMeasures.cpp:678-730`). This is not SICN. Relocation uses barycentric targets and a golden-section line search over xi in [0,2] (`meshRelocateVertex.cpp:141-179,327-362`); its default 1e-2 tolerance (`meshRelocateVertex.h:15`) is dimensionless search tolerance, not a boundary or manufacturing tolerance. It sweeps all eligible interior stars, rather than only the 210 poor cells. SICN improvement, positive orientation, runtime and final SICN>=0.1 are not guaranteed by this source path.

This is a necessary opportunity for an interior-coordinate hypothesis, not proof that a usable position exists or the barycentric/Gamma objective will find it.
