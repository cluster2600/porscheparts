# Held CGAL phase controller with one absolute per-job budget

This is an unrun source-only successor. No native wrapper is implemented here, no fixture geometry is generated, and no Docker/compiler/native/scientific import or test was executed. All predecessor files remain unchanged. Root owns source review, mock tests, runtime/resource preflight and each separately authorized compile, four-job fixture or one-job head child.

The selected CLI is run_cgal_phase.py. It imports the adjacent hash-bound run_finest_endpoint_metadata.py, which imports its adjacent hash-bound run_finest_endpoint_preflight.py. This repeats the existing c219/a884/b214 module layout at the same repository depth, so ROOT parents[3] and relative task input guards retain their meaning. Only that selected CLI is a new supported caller. The copied base and metadata modules retain their old unselected CLI/preparation functions for byte-reuse provenance; do not invoke those inherited old standalone CLIs as CGAL callers.

The core is a copy of frozen b214e1ce with nine declared reversible literal substitutions. A job's started timestamp and deadline_at=started+budget are fixed BEFORE docker create. Setup uses the existing bounded create/inspect calls and exact ownership/image/resource/mount verification. Immediately before docker-start Popen, elapsed budget exhaustion refuses without launching attach. The monitor receives the same absolute deadline and original started timestamp; its wait uses only remaining budget. An unconditional post-poll/wait check catches an already-exited RC0 process or completion that otherwise skipped the loop. A final elapsed latch after cleanup refuses late completion even if the monitor had returned. There is no reset of the countdown after setup and no acceptance through a missing asynchronous timer callback.

Owned-ID cleanup is unchanged: never-started creation recovery by fresh name requires matching ownership/image; running or unknown state on a verified ID triggers kill; attach is waited/reaped; final exact ownership/image/stopped/PID0 metadata is checked before removing the owned container. Existing bounded cleanup calls may continue after the acceptance deadline; this deadline is a fail-closed launch/completion budget and not a promise that receipt writing or cleanup returns by that exact instant. Original signal handling, inspection protocol, per-call timeouts and optional-Tmpfs runtime substitution/restoration remain unchanged. Do not infer new peak resource measurements, independent OS PID absence or new signal-race coverage from this patch.

The metadata companion changes only its BASE_SHA to the new core. The phase runner changes only its descriptive docstring, META_SHA, the new private test path and the fixed native entrypoint allowlist to /bounded-distance. /usr/bin/c++ remains the compile entrypoint. All declared phase controls are unchanged: one compile job at2CPU/4GiB/300s/tmpfs1GiB; four fixtures at2CPU/512MiB/60s each/no tmpfs; one head job at2CPU/4GiB/300s/no tmpfs. MemorySwap equals Memory (no additional swap), network none, read-only root filesystem, exact hash-bound read-only sources and one owned writable /out. Jobs execute serially and stop on the first refusal; no automatic retry or phase chaining.

Eight prepared mock methods (unrun) cover: setup reaching the60s budget before Popen; already-exited Popen at60/61s; wait completion at61s; final cleanup completion at61s; ordinary setup-started completion; observer/monitor exception killing and reaping only the known ID; authority/control/input-pin refusal before native; and first failed fixture preventing later jobs with metadata restoration. Every subprocess, inspect, monotonic clock and host kill in the exercised core paths is mocked. Temporary roots are immediately resolved for macOS /var aliases. Pure helper dictionaries and fake native processes are labelled test inputs, not worker results.

A future root child must bind every new core/metadata/controller/test/source-delta/METHOD/held file, the exact wrapper/header/kernel/numeric policy, compile inputs or actual ELF, fixture configs/data/independent expectations or exact head source-ID arrays/proof+complete original target, and every prior source/actual-result review required for that phase. The child must bind the selected controller at its actual path, satisfy existing fixed phase/job-count/entrypoint/limits/mount guards and use a fresh output under work/962-engineering. Compilation, fixture numerical acceptance and head geometric distance remain separate reviews. The wrapper prep/hash is pending here, not invented; no actual child is supplied.

CGAL5.6 image57c6 and installed-header receipt are context pins only; a fresh root-owned image/runtime/resource preflight remains required. A later wrapper must explicitly preserve absolute mm, const input identity, full original target, exact selected source-ID coverage and conservative scalar-error enclosure/gap<=.0001mm/.0625mm budget. This controller does not assess numerical intervals or repair either prior CUB failure. No solver/material/strength/LPBF/physical/manufacturing admission follows.
