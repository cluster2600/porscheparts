# Fixed-shell cube generation: completed software witness

One bounded Gmsh 4.15.2 call generated a tetrahedral mesh from the existing literal 7 mm cube shell. The run preserved all eight fixed boundary coordinate byte strings, twelve tagged oriented triangles and boundary entity classifications. It produced **9 nodes and 11 positive tetrahedra**, with minimum native SICN **0.37759006531653144**; all eleven satisfy the unchanged **SICN ≥ 0.1** gate. This is a tiny software witness. It grants no cavity, cylinder-head, material, service-strength, LPBF or manufacturing qualification.

The complete [native report](results/fixture-report.json), [tiny arrays](results/arrays.json) and generated [binary MSH 4.1 file](results/cube.msh) are retained. The signed volume is **343 mm³**, with sixteen opposite internal face pairs and the exact twelve-face exterior. The worker checked all native metric lengths, positive Jacobians and volumes, no duplicate cells or orphan nodes, boundary identity, periodic absence and exact saved-reopen arrays, classifications and metric identity. No source input MSH was read; the newly written MSH was reopened.

The [independent stopped peer](reviews/result-peer.json) checked all saved JSON rows and reconstructed the tiny boundary, incidence, signed volumes and scalar SICNs using the standard library. Root's separate [Fraction check](root/independent-check.json) records every tetrahedron, exact volume 343 and maximum scalar/native SICN difference **2.220446049250313e−16**. Independent inspection of the MSH binary was limited to its hash, format header and little-endian sentinel; no independent element-section decode was performed. The MSH-to-array saved-reopen association remains the reviewed native worker's observation.

The explicit API attempts were one `generate(3)` and one write, with zero `optimize('Netgen')`, `createGeometry`, cache rebuild or solve calls. Options retain Algorithm3D 1, linear elements, Renumber 0, Optimize 0 and OptimizeNetgen 0. The [path-projected native log](results/native.projected.log) also records one Steiner insertion and one mesher-internal node relocation. Explicit call counters do not attest to the absence of such internal operations or establish node ancestry.

The worker took **0.4436205 s**, controller **0.6600665 s** and root **0.7772716 s**, with return code 0 and no stop. Limits were **30 s**, sampled **1 GiB RSS / 16 MiB output**, and two requested threads. The maximum of two RSS samples was **138,133,504 bytes**, not an unsampled peak. No hard OS CPU or address-space limit was applied. All 23 project input pins, three selected runtime pins and the separate NumPy origin hash matched before and after. Root observed the owned controller/worker pair and individually confirmed both absent after waiting for the controller; worker reaping is attributed to the frozen finalizer. This is not universal process-absence or complete package/OS/ABI/source-build attestation.
