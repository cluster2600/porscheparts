# External intake for one Porsche 993 dashboard specimen

This is the third-party evidence package for [issue #568](https://github.com/cluster2600/porscheparts/issues/568). Its target scenario is a **candidate M564, left-hand-drive, non-RS vehicle**. No vehicle, dashboard, scan or measurement has been admitted. The [public template](packet-template.json) deliberately has a null specimen ID, no files and no readings. It cannot establish a part number, fit, occupant safety or manufacturing readiness.

The [project charter](../../../docs/PROJECT_CHARTER.md) does not assign buying, dismantling, measuring, printing or fitting to the repository owner. A lawful outside contributor may offer evidence; receipt remains conditional on identity, privacy, rights and independent review. The [PET identity audit](../../../docs/reports/993-dashboard-variant-audit-20261106.md) leaves the non-RS M564 trim and knee-strip numbers unresolved. The historical [D01–D14 measurement plan](../../../parts/993-int-dashboard-trim-0001/evidence/measurement-plan.md) supplies measurands and capture ideas, but its older part-number assumptions do not resolve the identity gate.

## Package boundary

Create one opaque ID of the form `SPEC-993-DASH-XXXX` for **one physical vehicle and its removed parts**, plus one `SESSION-993-DASH-XXXX` capture campaign ID. Repeat the specimen ID in every off-repository asset and measurement manifest. Do not use a VIN, registration, owner name, address or other personal identifier as either ID. Keep raw photos, scans, calibration records and rights letters in a private `work/993-dashboard-intake/<specimen-id>/` quarantine; `work/` is ignored by Git. A public contribution may contain only redacted metadata and links to independently reviewed hashes. Do not commit raw captures or proprietary PET/workshop pages.

| Gate | Required outside evidence | Decision if absent or contradictory |
| --- | --- | --- |
| E1: variant | Redacted vehicle option label, model year, driving position and independent reading of the option code. | Hold the specimen; open a separate variant package if it is not M564 LHD non-RS. |
| E2: restraint boundary | Passenger-side reverse inspection showing whether a module or deployment flap is present; independent reviewer separate from the capture operator. | Stop the no-passenger-airbag candidate if either is present or unclear. |
| E3: trim identity | Photograph of the actual removed trim label, or its label area if absent; record an unreadable or absent part number as unknown. | Never infer the M564 number from `993 552 055 00` or an RS row alone. |
| E4: continuity | A JSON file manifest tying fitted views, removed/reverse views, host-body capture and every reading to the same opaque specimen and capture campaign IDs. | Do not combine unrelated vehicles or parts. |
| E5: rights and privacy | File-by-file creator, licence, permission to inspect and to publish redacted derivatives, byte count and SHA-256; redaction review. | Keep files private and refuse publication or geometry reuse until rights are verified. |

Capture the dashboard **fitted**, then **removed**, including its reverse and original attachments. Capture the body/vehicle host after removal, independently of the part and of the F0 CAD. Use calibrated scale references, instrument identity, at least three readings per D01–D14 measurand in each applicable state, units, uncertainty and repeatability. Record fitted-versus-removed deformation rather than treating one scan as the installation shape. Measure host datums, fastener centres and axes, mating faces, clearances and the original knee-strip anchors against the [independent interface contracts in PR #591](https://github.com/cluster2600/porscheparts/pull/591). The contracts and their reviewer decisions must be frozen before any reading is used to position CAD.

Use the existing [measurement record format](../../../catalog/templates/measurement-record.json), [capture protocol](../../../docs/CAPTURE_PROTOCOL.md) and [scan registry](../../../catalog/scans/README.md) for their own fields. Their schemas do not currently carry a same-specimen ID or per-file rights proof; the external packet manifest supplies those cross-file bindings. A `MEAS` or `SCAN` record must not acquire ad hoc fields that its validator rejects.

Copy `packet-template.json` as `work/993-dashboard-intake/<specimen-id>/packet.json`, then fill only observed evidence. Every asset path is relative to that packet directory and has a byte count and SHA-256. The E4 JSON file has `specimen_id`, `capture_campaign_id`, `asset_ids` and `measurement_record_ids`; the last two arrays list the IDs in the packet exactly, including the E4 asset itself. A reading reference uses `MEAS-ID:DIMENSION_ID`, where the dimension ID is a `readings[].dimension_id` in that exact record. The [packet schema](packet.schema.json) describes structure; `python3 scripts/check_993_dashboard_intake.py --packet work/993-dashboard-intake/<specimen-id>/packet.json` also checks file bytes, same-specimen binding and declared reading references. With no argument, the command checks that the tracked public template remains empty and blocked. The command can only hold a coherent private submission for independent review.

## Admission and publication

First verify asset bytes and SHA-256 values in quarantine, then compare the E1–E5 identity packet with the PET matrix and every measurement with the independent interface contract. Keep missing or conflicting readings null. Independent measurement, interface, rights/privacy and professional engineering reviewers hold separate roles. A metadata checker can at most mark a complete submission **held for review**; it cannot approve the specimen or an occupant-facing composite part. Any public decision record must cite the reviewed contract revision and file hashes while excluding personal data and raw source files.

Until such a packet exists and is independently accepted, the [assembly inventory](../assembly.json) retains `null` component transforms and `missing_data` interfaces. The [F0 images](../README.md) remain schematic.
